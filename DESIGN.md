# HAMDEE workspace design

Preserve the existing HAMDEE interface and workflows for one approved owner/admin. Partners and tenants are records; they do not receive portals in this milestone. Authentication and persistent property metadata use the existing vanilla workspace, not a new frontend framework.

The gold/brass branding, HAMDEE logo, Inter font, approximately13px interface text,232px desktop sidebar, pale limestone canvas, white cards, subtle borders, icons, navigation and card/table/detail hierarchy remain. The source assets are local in `public/shared/`; workspace-specific styling is in `public/workspace/foundation.css`. A static font-path alias preserves the inherited stylesheet URL without changing the shared asset bytes.

Property identity/revision, create/edit dialogs, reversible archive/restore reasons and audit history remain visible and attributable. Dashboard counts come from saved metadata. Unavailable financial modules do not display fabricated balances or treat zero as an accepted financial result. The development banner and unconfigured-backend state communicate the actual boundary.

Native forms/dialogs retain labels, keyboard dismissal/focus return, actionable errors and pending-state feedback. Drafts survive recoverable network/version errors and clear on session loss; stale responses cannot restore protected UI. Tables/tabs scroll within containers on mobile, and navigation remains collapsible. Respect reduced motion. No new motion or visual redesign was introduced by standalone packaging.

The current owner flow is managed email/password sign-in directly to Dashboard after server verification of the sole owner and enabled membership. It has no mandatory MFA, enrollment, QR/OTP screen or one-hour assurance freshness gate. Preserve CSRF protection, server session expiry, explicit logout and recovery preparation. Partners and tenants remain business records, not login accounts. Historical security checkpoint documents do not define the current login experience.

Form recovery should keep a failed sign-in actionable without resubmitting credentials automatically. An expired CSRF write proof can be renewed through a safe read while retaining an operational draft; saving again always requires an explicit action. Property search should distinguish an empty register from empty filtered results and offer a direct way to clear filters. These refinements reuse existing native controls, panel hierarchy, brass actions, white surfaces, Inter and compact spacing; no new visual direction or motion is selected.

Browser coverage includes desktop1440×1000 and mobile390×844, owner email/password login, property/history, empty/error/conflict states, keyboard access and late-response handling. Automated checks do not constitute full screen-reader or cross-browser certification. Test screenshots and reports are ignored artifacts, not public source.

## Owner operations additions

Staff Collections is an owner-managed custody workflow: collectors are business records, existing receipts identify collected money, and handovers move custody to company cash/bank without creating income. Keep collected, handed-over and held amounts separate by currency and expose dated statements and correction history from the backend. No staff login, permissions, invitations or dashboard is introduced.

The interface remains a dense HAMDEE ledger: white paper panels on limestone, charcoal text, brass primary actions, sage confirmations and amber exceptions. Reuse Inter, existing icons, native forms/dialogs, subtle borders and the 4px spacing rhythm. Prioritize collector/receipt selection and the handover review; do not animate money or introduce a new visual theme.

Navigation follows Dashboard, Villas & Properties, Car Rentals, Staff Collections, Expenses, Company Finance, Personal Finance, Partners & Investments and Reports. Properties retain their existing link and parent workspace, with rooms/rentals and maintenance inside that group. Staff Collections binds the Coordinator-approved v1 owner API; missing services display an explicit unavailable state with no fabricated totals or writable forms. Secondary car/full-finance modules remain unavailable. Minimum confirmed company account setup lives alongside handovers.

Staff money values are authoritative decimal strings in major currency units. Display their full precision without dividing by 100, rounding, currency conversion or client-side balance calculations. Receipt choices show saved property/room/customer labels and original receipt identity; only unlinked receipts are selectable. Pending cheques require no invented custody location and remain unavailable for handover. A direct company receipt requires the actual same-currency account and explicit owner confirmation. Handover corrections use a new reference and preserve reasons and prior records. Openings have no suggested amount or date; even zero requires owner confirmation.

Native staff dialogs preserve drafts after rejected writes, renew an expired CSRF proof only after an explicit action, and freeze uncertain submissions for an exact-key retry. Route/session changes abort reads/writes and remove protected drafts. Desktop/mobile contract tests inspect controls and exact API commands using synthetic response fixtures; financial service acceptance remains an independent integration gate. Property revision writes use the Coordinator-required `X-Hamdee-Property-Revision` header with the existing quoted revision value and require the matching backend repair.

The receipt picker loads additional saved receipts only through an explicit Load more receipts button. It reuses the initial cutoff and optional property filter, passes opaque cursors unchanged, and merges pages by source kind and receipt ID. Loaded choices and a selected receipt remain alongside the collector/custody/notes draft; a failed page retains the cursor for an explicit retry. A first page containing only already-linked receipts still opens the picker when more pages exist. Closing/resetting the dialog cancels its page request. Native controls and existing compact styles remain; no motion is added.
